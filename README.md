なぜ WSL2 上でファイルを扱う方が良いのか？

ご認識の通り、Windows 上で Docker を使う場合、WSL2 (Windows Subsystem for Linux 2) を利用するのが現在の主流です。

WSL2 は Windows 上で Linux カーネルを直接実行する仕組みですが、ファイルの置き場所によってパフォーマンスに大きな差が出ます。

- 遅いケース: WSL2 の中から Windows のファイルシステム（/mnt/c/Users/...など）にアクセスする場合。
  - OS 間のファイルシステムの変換処理が挟まるため、特に npm install のように大量の小さなファイルを読み書きする操作が非常に遅くなります。
- 速いケース: WSL2 の中の Linux ファイルシステム（Ubuntu なら~/、つまり/home/your_username/以下）にファイルを置く場合。
  - Linux ネイティブのファイルアクセスになるため、変換処理がなく、本来のパフォーマンスが発揮されます。

結論として、プロジェクトのファイルは WSL2 のファイルシステム内に置いて作業するのが断然おすすめです。

ステップ 1: 環境構築（Docker と WSL2 のインストール）

まだ Docker や WSL2 をインストールしていない場合は、以下の手順でセットアップしてください。

1.  WSL2 のインストール:
    - Windows の検索バーで「PowerShell」と入力し、「Windows PowerShell」を右クリックして「管理者として実行」を選択します。
    - 開いた青いウィンドウで、以下のコマンドを実行します。

1 wsl --install - これにより、必要な Windows 機能の有効化と、標準ディストリビューションである「Ubuntu」のインストールが自動で行われます。 - 完了後、PC の再起動を求められる場合があります。再起動後、Ubuntu の初回起動時に Linux 用の「ユーザー名」と「パスワード」の設定を求められる
ので、入力してください。（Windows のパスワードとは別で構いません）

2.  Docker Desktop のインストール:

    - Docker 公式サイト (https://www.docker.com/products/docker-desktop/)から「Docker Desktop for Windows」をダウンロードします。
    - インストーラーを起動し、指示に従ってインストールします。途中で「Use WSL 2 based
      engine」という趣旨のチェックボックスがオンになっていることを確認してください。
    - インストール完了後、PC の再起動またはログアウト/ログインが必要になる場合があります。

3.  VS Code と WSL 拡張機能（推奨）:
    - もし VS Code をお使いでなければ、公式サイトからインストール (https://code.visualstudio.com/)してください。
    - VS Code を起動し、左側の四角いアイコン（拡張機能マーケットプレイス）を開きます。
    - 検索バーに「WSL」と入力し、Microsoft 製の「WSL」拡張機能をインストールします。これにより、WSL 内のファイルを Windows の VS
      Code から直接、かつ高速に編集できるようになります。

ステップ 4: Docker 環境の使い方

今後は、各日付の問題を解く際に以下の手順で専用のコンテナ環境を起動します。

（初回のみ）Docker イメージのビルド

1.  VS Code で WSL 内のプロジェクト（~/daily-web-practice）を開きます。
2.  VS Code のターミナル（Ctrl + @）で、以下のコマンドを実行します。

```
docker-compose build
```

- これにより、Dockerfile を元にした Node.js 環境の Docker イメージが作成されます。この作業は Dockerfile を変更しない限り、毎回行う必要はありません。

各問題への取り組み方

1.  VS Code のターミナルで、特定の日付（例: 20251126）の問題を解くために、以下のコマンドを実行します。

```
docker-compose run --rm -w /workspace/20251126 practice sh
```

- コマンド解説:
  - run --rm:
    practice サービスのコンテナを起動し、終了時に自動でコンテナを削除します（--rm）。これにより、毎回クリーンな状態で始められます。
  - -w /workspace/20251126:
    コンテナ内の作業ディレクトリを、指定した日付のフォルダに設定します。
  - practice:
    docker-compose.yml で定義したサービス名です。
  - sh:
    コンテナ内で実行するコマンドです。この場合、インタラクティブなシェルを起動します。

2.  コマンドを実行すると、ターミナルのプロンプトがコンテナ内のもの（例:
    /workspace/20251126#）に変わります。これで Docker コンテナの中に入れました。

3.  コンテナ内で、通常通り npm コマンドを実行します。

```
# 依存関係をインストール
npm install

# テストを実行
npm test
```

- node_modules は、ホストマシン（WSL 上）ではなく、この使い捨てのコンテナ内に作成されます。

4.  作業が終わったら、exit コマンドを実行するか、Ctrl +
    D を押してコンテナから抜けます。コンテナは自動的に削除され、node_modules も一緒に破棄されます。

これで、ホスト環境を汚すことなく、各問題に集中できる開発環境が整いました。
